## Answers and findings

**Fable usage for Claude Code (Max/Ultra).** Fixed and checked against a live
Max response (12 Nov, key names only). There is no `seven_day_fable` key: the
response lists per-model weekly limits in `limits[]` as `kind: "weekly_scoped"`
with `scope.model.display_name: "Fable"`. The reader now turns each scoped
limit into "Weekly (<model>)" after the 5-hour and weekly windows.

**Orchestration across harnesses; thread vs subagent.** Answered. Every
external harness (Claude Code, Codex, ACP agents) gets a `tenon` MCP server
with cross-harness delegation: an agent can hand a task to another harness
and model, for example a Codex thread asking Claude Code with Opus. The
delegated run is a child session (`parentID` = the calling thread), so it
shows as that thread's subagent, never as a new thread. Limits: depth 2, 4 at
once, a call waits up to 10 minutes. A harness's own subagents (Claude Code
Task, OpenCode subagents) are reported by that harness and shown in the same
subagent card. An ACP agent only gets the MCP server if it advertises HTTP
MCP support; whether OpenCode does is worth checking, since without it OpenCode
threads can't delegate. New threads come only from you (or a routine).

**Google writes.** Answered. Calendar events and Google Tasks are written to
Google (`POST/PATCH/DELETE` on the Calendar and Tasks APIs) only when the
Google connection was made with write access; a read-only connection keeps
changes local. Agent calendar changes land in the local calendar file and
reach Google on the next sync.

**Accounts page not syncing the calendar.** Answered. The Accounts page signs
in for mail only (Gmail read and compose). Google Calendar is a separate
connection on the Calendar settings page with its own sign-in. That's a design
gap, covered under [One Google sign-in](#one-google-sign-in).

**Branches don't show until the agent runs.** Needs repro. The branch is
fetched when each folder's store starts, and updates on a branch-change event.
The code path looks right, so we need the case: which page (Home composer,
thread composer, new thread), and does the folder show "No branch" or nothing?

**Command Code "not supported" on macOS.** Answered. Tenon has no platform gate
for Command Code: it has no built-in setup on either OS and is added as a
custom ACP agent. The "not supported" message came from the setup assistant's
own conclusion while it probed `/opt/homebrew/bin/command-code`. Likely the
installed CLI version has no ACP mode. Worth folding into
[the harness checklist](#harness-add-checklist).

**Codex disconnected after it updated.** Answered, likely cause. Codex runs
from the `binaryPath` setting, else `codex` on the PATH the app captured at
start. An update that installs to a different place (npm under another Node,
the standalone installer, Homebrew) leaves the old path dead until the app
restarts or the setting changes. Proposed fix: after an update, resolve the
command again, run `codex --version` from the new path, and offer to switch.
Small follow-up.

**Auto-permissions across harnesses; why only the Command Centre asks.**
Answered. Auto-accept is per thread folder ("Open a thread to turn this on. It
applies to that thread's folder"). Project threads where you turned it on stop
asking; the Command Centre runs in its own `.command-centre` folder, where it
was never turned on, so it asks. Claude Code starts in its user's default mode
except `bypassPermissions`, which Tenon moves to `default` so approvals reach
Tenon. Covered under [Permissions](#permissions).

**Steering stops OpenCode's subagents.** Answered, by design today. An external
harness runs its whole loop as one turn, so a steer asks the agent to stop and
starts a new turn with your message. Stopping the turn stops its subagents. The
built-in agent instead promotes the steer at the next step without stopping.
Covered under [Talk to the main agent while subagents run](#talk-to-the-main-agent-while-subagents-run).

**Subagent failed, parent keeps waiting (OpenCode).** Needs repro. Tenon-run
delegated children report errors back to the caller. A harness's own subagent
(OpenCode's) is only as visible as the harness reports it; if OpenCode doesn't
send a failure update, Tenon shows it as still working. Need a transcript of
one case.

**Stale commands in the subagent card; expanding shows only loading.** Needs
repro, then design. The card shows each subagent's last reported tool call; a
finished subagent keeps its last command. Proposed: show "Finished" or
"Failed" with the end time instead of the last command, and make the expanded
view the child thread itself. See [Subagent view](#subagent-view-and-trackers).

**Connection drops mid-turn.** Answered in outline. The turn ends with an
error and the thread keeps what arrived; nothing is retried automatically,
because a provider call can't be replayed safely. Claude Code and Codex threads
resume their own session on the next message. Worth a test per harness.

**Worktrees after subagents finish.** Answered. Tenon's delegated runs don't
create worktrees: they run in the caller's folder. A worktree you create for a
new thread stays until you remove it. A harness's own worktrees (Claude Code
`isolation: worktree`) are that harness's to clean up.

**Hooks and MCP servers.** Answered. Harnesses use their own MCP and hook
config (`~/.claude`, `~/.codex`, OpenCode config), and Tenon adds its `tenon`
MCP server. There's no Tenon UI to add MCP servers or hooks per harness. Design
item.

**Images and graphs in chat.** Answered, partly. Chat shows pasted images and
draws SVG diagrams in windows. I haven't confirmed how each harness's image
output (Codex's image model, a chart a tool saves to a file) arrives, so this
needs a test per harness. Design item: show image files an agent writes during
the turn inline.

## Design workshop

Each proposal says what changes for you, the options, and a recommendation.
These follow the approved Material 3 remaster tokens (no colour coding).

### Permissions

Today: a yellow warning card with the raw command and three buttons. It reads
like an error.

Proposal: a neutral card that says what will happen, in one line ("Run
`ls -la` and 2 more commands in `.command-centre`"), the commands collapsed
under it, and a split primary button: **Allow once** with a menu for *Allow
for this thread* and *Always allow in this folder*. **Deny** stays secondary,
with an optional reason the agent sees. Warning colour only for risky actions
(deleting, network, writing outside the folder).

Mode switch, like Codex and Claude Code, in the composer's model pill:
*Ask* (default), *Auto-edit* (file edits allowed, commands ask) and
*Full auto* (everything in the folder allowed; outside the folder still asks).
It sets the per-folder auto-accept that exists today, plus the matching mode
on Claude Code and Codex. Recommendation: build the card first, then the
switch.

### Command Centre composer

Today: a floating composer that tries to show the thread, writes and status at
once.

Proposal, built from what you look at: the composer stays one line until
focused. Above it, one strip at a time: the current answer while it streams,
then a compact "3 changes · 1 question · 2 running" row you can open. Writes,
background tasks and plan limits move into that row's sheet. Open question:
should the Command Centre show the whole conversation, or only the last
exchange with a link to the full thread?

### Background tasks panel

A Tasks button in the composer bar (badge with the count), opening a panel
like Claude Code's: running subagents, delegated runs, terminal commands and
routines, each with harness, elapsed time, last step and Stop. Finished ones
collapse to a count. This is also where per-subagent context goes (below).

### Subagent view and trackers

- The context ring stays the main agent's.
- The Tasks panel lists each subagent with its own context and tokens.
- A finished subagent shows Finished/Failed and the end time, never its last
  command.
- Expanding a subagent opens its child thread (read-only while it runs), not a
  loading state.

### Talk to the main agent while subagents run

Claude Code lets you talk to the main agent while its subagents keep working.
Tenon can offer this where the harness allows:

- Built-in agent and Tenon-delegated runs: possible now. The children are
  separate sessions, so a new message to the parent doesn't have to stop them.
  Needs a change so steering the parent doesn't cancel running children.
- Codex and ACP harnesses: their subagents live inside one turn, so any new
  message stops them. Option: queue the message until the turn ends (today's
  *Queue*), and say so in the composer.

Recommendation: make *Queue* the default while subagents run, and build
non-blocking steering for the built-in agent and delegated runs first.

### Skills page

A search box, then sections: Tenon, Claude Code, OpenCode, Codex, and each
added harness, each with a count and collapsed when long. A skill installed in
several places shows once with "also in: …". Tenon skills keep their switch.

### Harness add checklist

Before a harness is added, the assistant runs and shows a checklist:

1. Command found (path and version), and how it was installed (for updates).
2. ACP handshake (or app-server) answers.
3. Models listed.
4. A one-line prompt gets a reply.
5. Permissions reach Tenon (one approval round trip).
6. Steering behaviour (stops the turn or queues).
7. Subagents reported (yes/no).
8. MCP over HTTP supported (needed for delegation and app tools).
9. Usage limits readable (yes/no).
10. Platform notes (Windows `.cmd` shims, macOS PATH from the login shell).

Failures say what works without that step. To discuss: which steps block
adding, and which only warn.

### Model profiles

A Settings › Model profiles page, based on the tor-model-profile skill: each
model gets a profile (prompt rules that counter its known mistakes), shown and
edited per model, with an on/off switch and the date and benchmark it came
from. Tenon adds the active profile to that model's system prompt in every
harness that takes extra instructions. Building a profile (benchmark runs)
costs money, so it starts from a button that confirms the model, harness and
number of runs.

### Widgets

Home gets three cards: running tasks (from the Tasks panel), upcoming events
(next 3), and usage left per harness (the same plan windows the context menu
shows). Each card hides when it has nothing to show.

### Project switcher in the composer bar

The folder chip in the composer bar becomes a project picker (search, recent
first). Picking one opens that project's page with the draft kept.

### Sound effects

Replace the OpenCode sounds with a small Tenon set: done, needs you, error.
Short, soft, and off by default for "done". Needs sound design; the sound
settings already exist in Settings › General.

### VS Code themes

Import a VS Code theme JSON and map its `colors` (editor background,
foreground, accents, selection) onto Tenon's tokens; syntax colours map from
`tokenColors` to the code highlighter. Unknown keys fall back to the current
theme. Start with import from a file; a theme marketplace later.

### One Google sign-in

One Google account entry in Accounts with switches: Mail, Calendar, Tasks.
Adding a switch asks Google for that permission only. The Calendar page reads
the same account. Today's separate Calendar connection would migrate.
