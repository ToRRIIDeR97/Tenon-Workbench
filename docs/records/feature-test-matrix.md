# Feature test matrix

Recorded 2026-11-26 on commit `e125392b` for phase P1 of the
[mobile, thread sync and test pass programme](../../implementations/mobile-sync-programme/implementation.md).
The baseline run of every suite is in [test-baseline-2026-11-26.md](test-baseline-2026-11-26.md).

Each row is one feature a user or an agent can reach. `Source` names the route, IPC channel, HTTP
route, tool, Settings tab (`settings:<tab>`) or file that implements it; channels and routes of one
feature share a row. `Evidence` lists the tests that exercise it today. Unit tests sit beside the
code in `tenon/packages/*/src` or in `tenon/packages/*/test` and `tenon/packages/app/test-browser`;
Playwright specs are under `tenon/packages/app/e2e/` and run against a mocked server in Chromium.

Status words:

- `covered`: automated tests exercise the main behaviour.
- `gap`: no test, or only a thin slice, and an automated test could be written (closed in P3).
- `manual`: can only be checked by driving the real app; the note says what to drive.
- `blocked`: needs something this Windows computer lacks; the note says what.

A `covered` row whose note says its tests fail on the baseline is not protected until the baseline
repair (P3 of the plan) makes those tests pass again; `gap` remains for features with no automated
test of their main behaviour.

Paths below are relative to the repository root.
