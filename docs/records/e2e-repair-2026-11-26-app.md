# End-to-end and engine repair, 2026-11-26 (app part)

Part P3b of the [mobile, thread sync and test pass programme](../../implementations/mobile-sync-programme/implementation.md).
Each row is one failure from the [test baseline](test-baseline-2026-11-26.md), decided as `spec drifted` (the app is
right and the spec now asserts what it is meant to do), `app regressed` (the spec is right and the app was fixed) or
`feature removed`. Spec paths are under `tenon/packages/app/`. The thread-view failures are recorded by part P3a in
`docs/records/e2e-repair-2026-11-26-thread-view.md`.

Every Playwright run used `PLAYWRIGHT_PORT=3102 PLAYWRIGHT_SERVER_PORT=4102`.

## Cold dev server reload

Eight of these failures share one cause. The Markdown renderer runs in a worker
(`session-ui/src/components/markdown.worker.ts`, `markdown-stream.ts`, `ui/src/context/marked-parser.tsx`), so Vite's
start-up scan never sees its dependencies. The first page that renders Markdown on a fresh dev server makes Vite
optimize them and reload every open page; the dev server log says
`✨ new dependencies optimized: @shikijs/stream, shiki, katex, marked, marked-shiki, remend` then
`✨ optimized dependencies changed. reloading`. A test whose page reloads mid-way loses its state (the Command Centre
strip closes, a streamed write starts over). Which tests it hits depends on what runs first, which is why the baseline
run (five workers, cold server) failed them and later runs on a warm server passed them.

Evidence, with the `.vite` cache cleared before each run and the base `vite.config.ts`:

- the five canvas, document and agent-write acceptance specs with five workers: 4 of 27 failed;
- `e2e/acceptance` plus `functional-audit-fixes` with the default ten workers, twice: the run whose Vite log shows the
  reload failed 8 tests (six rows below, the archived-Project test and `notes-f` merge AC-3); the run whose log shows
  no reload passed all 98.

With `optimizeDeps.include` listing those six packages (as `@tenon/session-ui > …` and `@tenon/ui > …`, since the app
does not depend on them directly) Vite bundles them at start-up, no reload appears in the log, and the same commands
passed cold.
